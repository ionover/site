# План переноса сайта `krimea-taxi.ru` на Next.js + Tailwind

## Цель
Переписать текущую WordPress-одностраничку на современный стек `Next.js + Tailwind CSS`, сохранив основной контент сайта, улучшив структуру, производительность, внешний вид и удобство дальнейшей поддержки.

## Что есть сейчас
- Текущий сайт представляет собой простую лендинговую страницу.
- Контент уже можно взять из сохраненного HTML-файла:
  - `TAXI _ Лучшее таки по Крыму.html`
- Основные секции уже понятны:
  - первый экран;
  - услуги;
  - блок с машинами / фото;
  - преимущества;
  - сценарии поездок;
  - отзывы;
  - FAQ;
  - контакты;
  - цены;
  - страницы `policy` и `agreement`.

## Общий принцип работы
- Делать сайт как простой, быстрый и поддерживаемый лендинг.
- Не переносить WordPress как систему.
- Не копировать старую верстку один в один.
- Сначала сохранить смысл и контент, потом улучшать дизайн и структуру.

## Этап 1. Сбор контента - выполнено
- Извлечь из текущего HTML весь текст, ссылки, контакты и список секций.
- Отдельно собрать:
  - телефон;
  - email;
  - Telegram;
  - маршруты и цены;
  - FAQ;
  - отзывы;
  - названия услуг.
- Собрать все изображения из сохраненной папки ресурсов или скачать оригиналы в отдельную папку проекта.
- Проверить тексты на опечатки, повторы и пустые блоки.
- Статус: завершено, повторно не прорабатывать без отдельной необходимости.

## Этап 2. Подготовка структуры нового проекта - выполнено
- Создать новый проект на `Next.js`.
- Подключить `Tailwind CSS`.
- Выбрать `App Router`.
- Настроить базовую структуру папок, например:
  - `app/`
  - `components/`
  - `data/`
  - `public/`
  - `public/images/`
- Сразу настроить:
  - favicon;
  - базовые metadata для SEO;
  - удобные npm scripts.
- Статус: завершено, использовать как существующую базу проекта.

## Этап 3. Контент как данные - выполнено
- Вынести контент из JSX в отдельные структуры данных.
- Создать файлы наподобие:
  - `data/site.ts`
  - `data/prices.ts`
  - `data/faq.ts`
  - `data/testimonials.ts`
- Хранить в данных:
  - заголовки;
  - описания;
  - список услуг;
  - маршруты и цены;
  - контакты;
  - ссылки на мессенджеры.
- Это нужно, чтобы будущие ИИ и владелец сайта могли менять текст без переделки компонентов.
- Статус: завершено, новые изменения вносить через существующие `data/*`, а не возвращаться к ручному переносу контента.

## Этап 4. Первый локально видимый экран
- На этом этапе основной результат: сайт уже открывается локально в браузере без ошибок через `npm run dev`.
- Достаточно одной рабочей страницы:
  - `/` — главная.
- Не делать отдельные страницы `policy` и `agreement` на этом этапе, если они мешают быстрее увидеть главную страницу.
- Собрать простой черновой layout без финального дизайна:
  - шапка;
  - основной контент;
  - подвал.
- Собрать на главной минимальный набор секций в таком порядке:
  - `Header`
  - `Hero`
  - `Services`
  - `Pricing`
  - `Contacts`
  - `Footer`
- Для `Hero` на этом этапе обязательно вывести:
  - номер телефона как кликабельную ссылку `tel:`;
  - кнопку или ссылку на Telegram;
  - изображение машины `i.jpeg`;
  - нейтральный текст-описание сервиса;
  - небольшой список преимуществ.
- Допускаются заглушки в текстах и изображениях, если они не ломают общую структуру страницы.
- Критерий завершения этапа:
  - главная страница рендерится локально без ошибок;
  - видны основные блоки;
  - телефон кликабелен;
  - Telegram-ссылка выведена;
  - картинка машины отображается.

## Этап 5. Укрепление структуры главной
- После появления первой локально видимой версии не расширять сайт в стороны, а привести главную к нормальной поддерживаемой структуре.
- Разбить уже собранную главную страницу на независимые компоненты:
  - `Header`
  - `Hero`
  - `Services`
  - `Pricing`
  - `Contacts`
  - `Footer`
- Подключить эти компоненты к данным из `data/*`, не возвращая тексты обратно в JSX.
- Если каких-то данных еще не хватает, использовать аккуратные заглушки в самих `data/*`.
- Добавить простое верхнее меню для общей картины сайта.
- Меню на этом этапе может быть черновым:
  - логотип или название;
  - телефон;
  - ссылки на секции.
- Критерий завершения этапа:
  - главная собрана из компонентов;
  - контент управляется через `data/*`;
  - структура страницы читается и легко меняется.

## Этап 6. Первый проход по визуалу
- Только после стабильной черновой структуры переходить к оформлению.
- Не повторять старый WordPress-вид и не усложнять интерфейс декоративными элементами.
- На этом этапе улучшать только то, что не меняет архитектуру:
  - отступы;
  - типографику;
  - цвета;
  - карточки;
  - размеры блоков;
  - состояние кнопок и ссылок.
- Приоритеты:
  - хорошая читаемость;
  - заметный номер телефона;
  - заметная ссылка на Telegram;
  - аккуратный первый экран с фотографией машины;
  - понятное визуальное разделение секций.
- Обязательно исправить:
  - опечатки;
  - пустые заголовки;
  - лишние блоки;
  - визуальный шум.
- Критерий завершения этапа:
  - страница выглядит аккуратно;
  - блоки визуально различимы;
  - интерфейс остается простым и не мешает дальнейшим правкам.

## Этап 7. Функциональность
- Добавить кликабельные контакты:
  - `tel:`
  - `mailto:`
  - ссылка на Telegram.
- Добавить якорную навигацию по секциям после того, как структура главной устоится.
- Сделать простое адаптивное меню для мобильных устройств.
- Не добавлять форму заявки в MVP, если она не нужна для первого запуска.
- Критерий завершения этапа:
  - все основные способы связи работают;
  - ссылки в меню ведут к нужным секциям;
  - мобильное меню хотя бы базово работает.

## Этап 8. SEO и производительность
- На этом этапе сделать только базовый технический минимум, без сложной SEO-стратегии.
- Прописать:
  - `title`;
  - `description`;
  - базовые Open Graph metadata;
  - корректные заголовки `h1-h3`.
- Использовать `next/image` там, где это не усложняет код без пользы.
- Оптимизировать изображения, начиная с главного изображения машины.
- Проверить, чтобы сайт оставался легким и без лишнего JavaScript.
- Убедиться, что на странице нет мусора, пришедшего из WordPress.
- При желании позже можно отдельно добавить:
  - `robots.txt`;
  - `sitemap.xml`;
  - canonical.

## Этап 9. Тексты и доверие
- Переписать тексты в более аккуратный и уверенный стиль.
- Устранить спорные или слабые формулировки.
- Проверить, что на сайте явно и удобно видны:
  - имя;
  - телефон;
  - способы связи;
  - условия отмены;
  - ориентировочные цены.
- При необходимости добавить блок:
  - “Как проходит заказ”;
  - “Почему мне доверяют”.
- Если пока нет уверенности в формулировках, оставить нейтральные временные тексты и доработать их после просмотра страницы в браузере.

## Этап 10. Проверка качества
- Проверить сайт на:
  - мобильном экране;
  - планшете;
  - десктопе.
- Проверить:
  - все ссылки;
  - якоря;
  - контакты;
  - цены;
  - читаемость текстов.
- Убедиться, что новый сайт не потерял важный контент со старой версии.
- Отдельно проверить, что страница не ломается, даже если часть данных пока остается заглушкой.

## Этап 11. Деплой
- Выбрать хостинг:
  - `Vercel` как основной простой вариант;
  - либо другой статический/Node-хостинг.
- Подключить домен.
- Настроить production-сборку.
- После публикации проверить:
  - HTTPS;
  - редиректы;
  - индексацию;
  - корректность метаданных.
- Если `policy` и `agreement` к этому моменту еще не готовы, осознанно решить:
  - публиковать сайт без них;
  - или добавить временные страницы-заглушки перед релизом.

## Что считать первой рабочей версией
- Главная страница открывается локально без ошибок.
- На главной есть хотя бы:
  - первый экран;
  - услуги;
  - цены;
  - контакты.
- Телефон и Telegram работают.
- Страница уже собрана из компонентов и данных.
- Сайт можно дальше улучшать без переделки основы.

## Рекомендации для будущего ИИ
- Начинать не с дизайна, а со структуры контента и компонентов.
- Сначала сделать рабочий MVP, потом улучшать визуальную часть.
- Все тексты и списки хранить отдельно от компонентов.
- Если контент из старого сайта выглядит слабым, не копировать его механически, а аккуратно переписать.
- Если в проекте появятся новые фотографии, складывать их в `public/images/`.
- Если появится форма заявки, делать ее как отдельный, минимальный и надежный блок.

## Следующий практический шаг
- Начать этап 4 и как можно быстрее добиться первого локального результата в браузере.
- Порядок действий:
  - собрать `/` как единственную рабочую страницу;
  - вывести `Header`, `Hero`, `Services`, `Pricing`, `Contacts`, `Footer`;
  - подключить `i.jpeg` в первый экран;
  - сделать кликабельный телефон и ссылку на Telegram;
  - убедиться, что `npm run dev` поднимает страницу без ошибок.
